# Risk Register

Last updated: 2026-05-17

| ID | Risk | Level | Impact | Mitigation | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| R-003 | Governance drift between roadmap/planning artifacts and implemented code | High | Future planning or reviews may make incorrect stage and scope decisions | Reconcile `docs/ROADMAP.md`, supersede stale planning notes, and keep the task ledger current | Mitigated |
| R-004 | Missing active-focus and rules artifacts weakens change control | Medium | Agents may operate without a current bounded objective or explicit tool-governance anchors | Add a current-focus document or equivalent lightweight rule set before major new work | Mitigated |
| R-005 | Stale documentation can hide actual release readiness and integration scope | Low | Teams may under-test or over-test the wrong slice of the system if roadmap and planning artifacts are not refreshed after major changes | Re-run sync-discovery before major decisions, keep governance artifacts current after significant changes, cite the alignment note when older planning documents are referenced, and record validated story evidence for settlement review/action/reopen workflows | Mitigated |
| R-006 | Missing formal code-review and security-review artifacts for accounting and integration surfaces | Medium | Release or readiness decisions may be made without explicit review evidence on financial and external-system changes | Require review artifacts before release-readiness decisions or high-risk production changes | Mitigated |
| R-007 | Hardcoded Hermes API token in compose configuration | High | Repository disclosure exposes a reusable credential and weakens secrets governance | Remove the committed token, rotate it, and inject the value from environment or secret storage | Mitigated |
| R-008 | Previously committed MCP and Hermes credentials may still be valid outside the repository | High | Historical exposure remains exploitable even after config remediation if the same credentials are still active | Rotate exposed credentials and re-enter them through secure prompts or environment variables | Open |
| R-009 | Published layout mutation causing terminal instability | Medium | Directly editing a layout used by active terminals could cause frontend crashes if schema changes mid-session | Enforce read-only status for published layouts in Slice B; require new versioning for updates. | Mitigated |
| R-010 | Invalid schema injection via admin CRUD | Low | Malicious or malformed JSON could crash the terminal or bypass security | Strict schema validation via `PosLayoutSchemaValidator` in Slice B backend. | Mitigated |
| R-011 | Rendering lag on low-end tablets from complex layout grids | Medium | UI performance degradation during busy shifts | Limit max grid dimensions in validator; optimize React rendering in Slice C. | Mitigated |
| R-012 | Missing product data for layout tiles (deactivated/deleted items) | Low | Tiles rendering as empty or causing frontend errors | `ProductGrid` must handle missing product lookups gracefully by rendering "Unavailable" state. | Mitigated |
| R-013 | Concurrent layout resolution conflicts | Low | POS might fetch inconsistent versions during a mid-shift transition | Terminal fetches layout on load or after transaction; resolution logic uses `latest()` active layout. | Mitigated |
| R-014 | Coordinate drift/orphaned tiles on grid resize | Low | UI rendering tiles that are outside the current grid dimensions | Frontend validation and backend coordinate stripping during dimension decrease. | Open |
| R-015 | Drag-and-drop accessibility or Z-index conflicts | Low | Editor becomes unusable on specific browsers or small admin screens | Standardize on dnd-kit and use portal-based overlays for drag previews. | Open |
| R-016 | Audit log storage bloat | Low | Logging full JSON schemas could quickly consume database storage | Store only layout metadata (ID, version, name) and diffs, not full schemas in audit logs. | Mitigated |
| R-017 | Rollback product availability drift | Low | Rolling back to an old layout may reference products that are now deactivated/deleted | `ProductGrid` already handles missing products by rendering "Unavailable" state; ensure rollback re-validates current product state. | Mitigated |
| R-018 | Inventory quantity corruption during stocktake posting | High | Financial reporting errors and operational stock mismatches | Atomically update `branch_inventories` using database transactions and immutable `InventoryMovements`. | Mitigated |
| R-019 | Double-posting of stocktake sessions | High | Multiplied inventory impact leading to massive stock discrepancies | Implement a "Posted" state guard and status-lock check before movement generation. | Mitigated |
| R-020 | Approval bypass for stock variance adjustments | Medium | Financial accountability gap / internal theft risk | Enforce server-side `inventory.stocktake.approve` permission checks and reason-code requirements. | Mitigated |
| R-021 | Race condition during concurrent counting/posting | Medium | Overwriting stock updates if sales occur during the counting phase | Implement snapshot-based "Expected Stock" and record movements relative to the session's counting window. | Mitigated |
| R-022 | Incorrect financial aggregation in reports | High | Misleading financial data and accountability failures | Mandatory unit tests for the Query Service with complex payment/reversal scenarios. | Mitigated |
| R-023 | Unauthorized cashier data exposure | Medium | Privacy breaches and internal friction | Strict RBAC gating and "Own-Only" scope for non-managerial roles. | Mitigated |
| R-024 | Cross-branch report leakage | High | Operational security breach | Enforce `BelongsToBranch` trait and global scopes in reporting queries. | Mitigated |
| R-025 | Settlement lock bypass in reporting | Medium | Auditing inconsistencies | Surface settlement status in the report UI and prevent "Re-calculating" locked historical data. | Mitigated |
| R-026 | Product Catalog CRUD UI unavailable for non-technical users | Medium | Admin/product setup requires technical intervention (seeders, SQL, or central import) | Track as future Back-Office Admin/Product Management epic or release-readiness item. | Open |
| R-027 | POS rounding and inclusive tax/discount math divergence | Medium | JS (frontend) and PHP/BCMath (backend) precision mismatches could lead to ₱0.01 discrepancies in receipt printouts vs. reporting logs | Enforce consistent rounding (e.g. standard half-up to 2 decimals) and treat all frontend display margins strictly as advisory | Mitigated |
| R-028 | Mixed-cart statutory discount validation bypass (SC/PWD) | High | Applying SC/PWD statutory discounts to non-eligible items (such as promotional bundles, alcohol, or tobacco) | Strict line-level `is_discountable` validation during sale creation math in checkout service (isolation is fully verified; transaction-level computation remains deferred to a future statutory discount slice) | Mitigated |
| R-029 | Inventory Valuation Cost Drift | High | Mathematical rounding errors in dynamic WAC recalculation over time | Enforce `bcmath` operations at a precision scale of 4 for WAC computation, validating against manual mathematical vector matrices in tests | Mitigated |
| R-030 | Double-Receiving Race Conditions | High | Concurrent posted vouchers for the same product leading to overlapping stock valuation updates | Apply pessimistic row-level locking (`pessimisticLock()`) inside atomic database transactions before updating inventories | Mitigated |
| R-031 | Procurement Cross-Branch Leakage | High | Assigned branch clerks or branch managers accessing POs or GRVs belonging to other branches | Enforce Laravel global scopes automatically filtering by the user's active session branch | Mitigated |
| R-032 | Missing Expiry Safety Parameters | Medium | Physical ingestion of perishable items without lot or expiration records | Officially mitigated via Story 26.1 planning lock (database model, validation gates, and FEFO allocation rules frozen in `docs/roadmap/stories/story_26.1_expiry_lot_and_fefo_scope_lock.md`) | Mitigated |
| R-033 | Unauthorized Inbound Adjustments | Medium | Fraudulent receiving updates bypassing PO review processes | Gate posting strictly behind server-side `procurement.receiving.post` permission checks | Mitigated |
| R-034 | Procurement CSV Injection | Low | Cell-level formula injection in exported files leading to CSV exploits | Enforce cell-level sanitization for all Excel executable prefixes (`=`, `+`, `-`, `@`) on exported CSV lists | Mitigated |
| R-035 | Supplier Returns WAC Valuation Cost-Drift | High | Negative stock valuation adjustments from returned items distorting branch COGS and gross margins | Recalculate WAC upon return posting at precise received line costs using bcmath decimal scale 4, verified via WAC Recalculation Service. | Mitigated |
| R-036 | Auto-reorder Scheduler Scope Leakage | High | Background auto-reorder daemon running without active context, creating invalid or cross-tenant purchase orders | Enforce fail-closed TenantContext booting during console job serialization and queue runtime checks. | Mitigated |
| R-037 | 3-Way Match AP Liability Race Conditions | Medium | Discrepancies in invoiced vs. received quantity resulting in incorrect accounts payable updates or double-posted QBO sync | Pessimistic row locking on matches; enforce strict unit-cost validation thresholds with QBO outbox queuing gates. | Mitigated |
| R-038 | Split PO Multi-branch Boundary Violations | High | Corporate buyers injecting unauthorized branch POs or leaking data across tenant-branch boundaries | Enforce server-side branch allocation checks and partition splits into branch-scoped children POs immediately upon creation. | Mitigated |
| R-039 | Subscription Bypassing via Direct DB Queries or Queues | High | Unauthorized tenants accessing premium features by bypassing the middleware | Standardized hasFeature/withinLimit checks applied in background queue workers and API routes | Mitigated |
| R-040 | Resource Limit Checking Performance Degrades | Medium | Recursive branch/user counting queries on every request load slowing down system response | Enforce limit checking strictly during write actions (like creating a branch) instead of read page loads | Mitigated |
| R-041 | Legacy Tenant Onboarding Disruption | High | Existing active customers losing access to modules after subscription system launch | Legacy grandfathering migration automatically seeds existing active accounts to the professional tier | Mitigated |
| R-042 | Inter-Branch Transfer Stock Movement Concurrency Race | High | Concurrent dispatch/receipt or stock underflows during active branch-transfer sessions | Wrap movement logic in atomic transactions, use pessimistic lockForUpdate(), and strictly enforce status gates. | Mitigated |
| R-043 | Invoice sequence concurrency race condition | High | Duplicate or skipping invoice assignment under high cashier concurrent checkout volume | Pessimistic locking (`lockForUpdate`) on sales machine profiles during atomic incrementing transactions. | Mitigated |
| R-044 | Compliance and accreditation audit exposure | Medium | Legal or tax penalties if internal diagnostic audit logs are represented as officially certified BIR rolling chains | Enforce strict "Draft - For Diagnostic Validation" watermarks, clear training label watermarks, and limit code representation to "baseline audit-readiness". | Mitigated |
| R-045 | Training mode data leakage into production Z-reports | High | Production GCT and tax liabilities corrupted by simulation transactions | Complete database-level isolation of training transactions, distinct `TRAIN-INV-*` prefixing, and explicit Z-Report extraction exclusions. | Mitigated |
| R-046 | Compliance and data loss exposure in Epic 28 Phase 2 Controlled Offline Sales | High | Sequence gaps, data loss, or illegal compliance claims if offline mode is rolled out prematurely | Restrict release to early partner pilots; default enabled but support tenant/branch/terminal toggles; provisional watermark receipts; server-authoritative reconciliation; defer final review post-development. | Mitigated |
